# OKTB / Terminal Permit / LOI: autosave and ready-to-download PDFs

## ข้อตกลงที่ยืนยันแล้ว

- ผู้มีสิทธิ์ดูเอกสารดาวน์โหลด PDF ไม่มี Draft / Sample / Not Approved ได้ทันที ไม่ต้องผ่านเจ้าของอนุมัติทีละฉบับ
- เพิ่ม autosave รายละเอียดเอกสาร ไม่ใช่เพียงผู้ติดต่อและลายเซ็น
- ไม่เปลี่ยนสิทธิ์ Crew / Visitor ไม่เปิดเอกสารให้สาธารณะ และไม่อนุญาตข้อมูลบุคคลจริงโดยปริยาย ระบบทดลองยังใช้ข้อมูลสมมติ
- ข้อตกลงนี้ยกเลิกขั้นอนุมัติก่อนดาวน์โหลดเฉพาะเอกสารสามประเภท ไม่เปลี่ยน Knowledge base, Finance หรือการเผยแพร่ตัวอย่างสาธารณะ
- ยังไม่ deploy ในขั้นออกแบบนี้

## ขอบเขตหน้าฟอร์ม

1. ยุบรายละเอียด Terminal Permit และรายละเอียด LOI เป็นค่าเริ่มต้น
2. ยุบส่วนเลือกคน / แก้ไขหัวข้อและรายละเอียดตาราง รวมถึงแต่ละหัวข้อย่อยของ Permit
3. แต่ละคอลัมน์ชื่อใช้ช่อง Name - Surname ช่องเดียว: พิมพ์เพื่อเลือกรายชื่อจากรายการที่ได้รับสิทธิ์ หรือพิมพ์ชื่อเอง ช่องอื่นเติมเมื่อเลือกคน ไม่เขียนกลับ Crew members
4. เก็บ person ID แยกจากข้อความชื่อ หากแก้ชื่อให้เป็นข้อความอิสระ ให้ยกเลิกการเชื่อม person ID; รายชื่อซ้ำต้องมีตัวเลือกแสดงประเภท/ข้อมูลช่วยแยกโดยไม่เปิดข้อมูลเกินสิทธิ์
5. ขยายคอลัมน์ชื่อ ลดคอลัมน์ลำดับและข้อมูลสั้น ช่องที่อ่านไม่ได้บนมือถือใช้เลื่อนเฉพาะตาราง ไม่ทำให้ทั้งหน้าล้น
6. เปลี่ยนหัวข้อเริ่มต้น Full Name & Family Name เป็น Name - Surname รวมทั้งตารางเดิมที่ยังใช้หัวข้อเริ่มต้นนั้น ไม่ทับหัวข้อที่ผู้ใช้ตั้งเอง
7. LOI เลือกคนแล้วแสดงและเปิดส่วนตรวจ Personal Detail ทันที เติมค่าที่มีจาก Crew members รวมทั้งชื่อเต็ม ข้อมูลที่ไม่มีเว้นไว้ ไม่เดาการแยก Surname/Given name จากชื่อเต็ม และแก้ได้เฉพาะเอกสาร
8. ปุ่มดาวน์โหลดระบุประเภทเอกสาร ไม่ใช้ข้อความ PDF (ร่าง); PDF และชื่อไฟล์ไม่มีตราร่าง/ตัวอย่าง หน้าฟอร์มยังมีคำเตือนระบบทดลองนอกพื้นที่เอกสาร

## รายชื่อสถานทูตและสถานกงสุล

- เพิ่มรายการ Royal Thai Embassy และ Royal Thai Consulate-General ทั่วโลกตามสารบบกระทรวงการต่างประเทศ; กงสุลกิตติมศักดิ์ไม่รวมในชุดเริ่มต้นนี้
- เมื่อเลือกให้แสดงชื่อ, ที่อยู่, โทรศัพท์, แฟกซ์, อีเมล แยกบรรทัดตามลำดับทั้งพรีวิวและ PDF
- อีเมลทั่วไปและอีเมลวีซ่าแสดงแยกพร้อมประเภท ไม่ใส่เครื่องหมาย slash ท้ายข้อความโดยไม่จำเป็น
- ตรวจข้อมูลแต่ละแห่งจากเว็บไซต์ทางการ เก็บ URL และวันที่ตรวจ ไม่ใช้ข้อมูลตัวอย่างของ Dhaka เป็นค่ากลางของสถานทูตอื่น
- รายการไม่มีแฟกซ์/อีเมลที่ตรวจพบให้ไม่แสดงบรรทัดนั้น ไม่เดา ข้อมูลที่ยังตรวจไม่ครบต้องแสดงสถานะตรวจไม่ครบในตัวเลือก ไม่อ้างว่าตรวจครบทั่วโลก
- แก้ข้อมูลผู้รับในเอกสารเฉพาะฉบับได้ ไม่เปลี่ยนสารบบส่วนกลางโดยอัตโนมัติ การอัปเดตสารบบไม่เขียนทับฉบับที่แก้ไว้
- เพิ่มข้อมูลสถานทูตต้องตรวจการตัดบรรทัด/จำนวนหน้า LOI; ไม่ตัดข้อมูลทิ้งเพื่อบังคับหนึ่งหน้า

## ที่เก็บและสิทธิ์

ใช้ Neon ส่วนตัวที่ Operations ใช้อยู่ ไม่เก็บเนื้อหาเอกสารใน GitHub สาธารณะหรือ browser storage

- ระเบียนเอกสารแยกตาม Job + Service (ถ้ามี) + ประเภทเอกสาร; ไม่ใช้ข้อมูลข้าม Job/Service โดยไม่ตั้งใจ
- LOI เก็บรายละเอียดเพิ่มเติมแยกตาม person ID ภายในฉบับ เพื่อสลับคนแล้วไม่ทับรายละเอียดอีกคน และดาวน์โหลดครั้งละคน
- เก็บฟิลด์ที่แก้ได้ตามรายการอนุญาต: วันออกเอกสาร, วันเรือเข้า/ดำเนินการ, Airline/ผู้รับ, รายชื่อที่เลือก, Subject, หัวตาราง, แถวตาราง, รายละเอียดเพิ่มเติม LOI และตำแหน่งผู้ลงนาม
- Contact person, โทรศัพท์, ชื่อผู้ลงนาม และภาพลายเซ็นยังใช้ค่าเริ่มต้นส่วนตัวตามบัญชีเดิม ไม่คัดลอกค่าเริ่มต้นของคนหนึ่งไปเผยให้ทุกคน
- การอ่าน/ดาวน์โหลดตรวจ session และสิทธิ์ Crew/Visitor ปัจจุบันทุกคำขอ การแก้ต้องมีขอบเขตแก้ Job หรือ Service เดิม และสิทธิ์แก้ข้อมูลบุคคลประเภทที่เกี่ยวข้อง ไม่ใช้ PIC เป็นการเพิ่มสิทธิ์
- Permit แยก payload/read projection ของ Crew กับ Visitor; บัญชีที่มีสิทธิ์ประเภทเดียวไม่อ่านหรือเขียนทับตารางอีกประเภท รวมทั้งแถวที่กรอกเอง Staff/Agent/Car ถือเป็นส่วน Visitor ตามการจัดสิทธิ์เดิม
- Service ต้องเป็น Crew Change และอยู่ใน Job ที่ร้องขอ ยังไม่ขยายเอกสารไป Service ประเภทอื่น
- Job-level document ใช้ขอบเขตแก้ Job; Service-level ใช้ขอบเขตแก้ Service การตั้งค่า account ไม่ใช่การให้สิทธิ์แก้เอกสารทุก Job

## Autosave และความขัดแย้ง

- เปิดเอกสารโหลดข้อมูลที่บันทึกส่วนกลางก่อน render; ถ้ายังไม่มีใช้ต้นแบบเดิม โดยไม่ย้ายร่างในหน่วยความจำหรือข้อมูล offline ขึ้นส่วนกลางเงียบ ๆ
- บันทึกประมาณ 800 ms หลังหยุดพิมพ์; การเลือกคน เพิ่ม/ลบแถว และแก้หัวข้อเข้าคิวเดียวกัน
- แสดง ยังไม่บันทึก / กำลังบันทึก / บันทึกแล้ว / บันทึกไม่สำเร็จ อย่างตรงกับผลเซิร์ฟเวอร์
- ระหว่างเปลี่ยนแท็บ/คน รอคิวบันทึกหรือแจ้งค้าง ไม่อ้างว่า autosave สำเร็จเมื่อปิดหน้าเร็วเกินไป; เตือนเมื่อจะออกจากหน้าที่มีรายการยังไม่บันทึก
- ใช้ version และ base values เพื่อป้องกันการเขียนทับจากเครื่องอื่น; Conflict หยุด autosave และให้ตรวจค่าเดิม/ส่วนกลาง/ค่าของตนเอง ไม่มีปุ่มเขียนทับทั้งหมด
- ข้อมูลต้นทาง Job/Crew เปลี่ยน: แจ้งให้ตรวจความต่าง ไม่เขียนทับฟิลด์เอกสารที่แก้เอง รหัสบุคคลที่หมดสิทธิ์/ถูกลบไม่กลับมาเป็นแถวที่เปิดเผยได้
- บัญชีหรือสิทธิ์เปลี่ยน: ยกเลิกงานค้างและล้างพรีวิว ไม่ส่งคิวของบัญชีเดิมหลังเปลี่ยนบัญชี
- ปัญหาเครือข่ายเก็บการแก้เฉพาะหน่วยความจำและแสดงยังไม่บันทึก ไม่แอบเก็บข้อมูลบุคคลลง localStorage/IndexedDB

## การดาวน์โหลด

1. ตรวจข้อมูลที่จำเป็นและคิว autosave ให้เสร็จ หรือหยุดพร้อมบอกข้อผิดพลาด
2. ตรวจสิทธิ์และข้อมูลต้นทางปัจจุบันกับเซิร์ฟเวอร์สำหรับทั้งสามประเภท รวม OKTB ที่ยังไม่ได้ตรวจซ้ำก่อนดาวน์โหลดในโค้ดปัจจุบัน
3. ตรวจ revision ที่จะใช้สร้าง PDF ให้ตรงกับฉบับส่วนกลาง; หากเปลี่ยนให้ตรวจใหม่ ไม่ใช้ข้อมูลเก่าลงชื่อเป็นฉบับใหม่เงียบ ๆ
4. สร้าง PDF ของข้อมูลที่เลือก ไม่มีลายน้ำ Draft/Sample และไม่มีขั้นอนุมัติเจ้าของ ไม่มีการส่งให้สายการบิน/Terminal/สถานทูตอัตโนมัติ
5. การดาวน์โหลดไม่เปลี่ยนสถานะ Job/Service ไม่อ้างว่าเอกสารผ่านการรับรองจากหน่วยงานภายนอก และไม่อัปโหลด PDF ขึ้นส่วนกลาง/GitHub เพิ่มเอง

## Offline

คงระบบเอกสาร offline แยกจากฉบับส่วนกลาง ใช้ข้อมูลสมมติเท่านั้น การบันทึกยังตามกลไก offline เดิม ไม่เพิ่ม sync อัตโนมัติ ฉบับตัวอย่าง offline ต้องมีป้ายตัวอย่างต่อไป; การดาวน์โหลดทันทีแบบไม่มี Draft ในงานนี้หมายถึงเอกสารออนไลน์ที่ผ่านสิทธิ์เดิม

## ทางเลือกและเหตุผล

- เก็บใน Neon ตามขอบเขต Job/Service: เลือกแนวทางนี้เพราะรองรับซิงค์ข้ามเครื่องและตรวจ version
- เก็บ browser storage: ไม่เลือกเพราะไม่ซิงค์ข้ามเครื่องและเสี่ยงเก็บข้อมูลบุคคลบนเครื่อง
- เก็บ GitHub: ไม่เลือกเพราะข้อมูลเอกสารมีข้อมูลบุคคลและไม่เหมาะกับการพิมพ์ autosave ถี่

## หลักฐานที่ต้องทดสอบก่อนส่งมอบ

- TDD สำหรับ validate payload, scope filtering, role/PIC grants, revision/conflict และการดาวน์โหลดทันที
- เปลี่ยนข้อมูลทุกชนิดแล้ว reload/เปิดอีกเครื่องยังเห็นข้อมูลเดิม; ข้อมูลไม่ปะปนระหว่าง Job/Service/ประเภท/คน LOI
- แก้สอง session พร้อมกัน, เครือข่ายล้ม, ออกจากหน้าเร็ว, เปลี่ยนบัญชี และถอนสิทธิ์ระหว่าง autosave/ดาวน์โหลด
- Crew-only/Visitor-only/Viewer/Editor/owner/anonymous ได้ผลตรงสิทธิ์ รวมแถวชื่อกรอกเอง
- ตารางหนึ่งช่องชื่อ เลือกชื่อซ้ำได้อย่างชัดเจน ทุกส่วนยุบค่าเริ่มต้น; LOI เปลี่ยนคนแล้วเปิด Personal Detail และแสดงข้อมูลใหม่ทันที
- PDF จริงทั้งสามประเภท ตรวจไม่มีตราร่าง มีหัวตาราง/ข้อมูลสถานทูตครบ ไม่ตัดแถว/อักษร ตรวจบน desktop, mobile และ iPad
- Offline ไม่เรียก endpoint autosave ส่วนกลางและไม่เปิดเผยข้อมูลออนไลน์
- สถานทูตทุกแห่งที่รายงานว่าตรวจแล้วมีแหล่งทางการและวันที่ตรวจจริง; รายงานรายการที่เข้าถึงแหล่งทางการไม่ได้อย่างชัดเจน

## สถานะ

บันทึกแบบจากขอบเขตที่ผู้ใช้ยืนยันแล้ว รอผู้ใช้ตรวจแบบฉบับนี้ ก่อนเขียนแผน implementation และเลือกวิธีลงมือทำตาม Superpowers ไม่อ้างว่า autosave หรือฉบับ PDF ใหม่ทำงานแล้ว
